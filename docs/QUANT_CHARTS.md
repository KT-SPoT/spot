# Quant 그래프

상권·고객 구성 화면은 주요 관측값 4개와 유동인구·주거인구·직장인구·매출액
분석 선택 버튼을 제공한다. 성별·연령은 서로 다른 분포이며 교차 고객 비율을
뜻하지 않는다. 주거·직장 인구에는 제공되지 않는 요일/시간대 그래프를 만들지 않는다.

## 표시 규칙

- 모든 막대는 0~100% 축을 사용하며 원문 비율을 표시한다. 합계가 다르거나
  일부 항목이 없더라도 재정규화하거나 보완 비율을 추정하지 않는다.
- 0은 `0%`, 결측·비정상 수치는 `미확보`로 표시한다. 숫자 문자열, 불리언,
  음수, 100 초과, NaN/Infinity를 비율로 그리지 않는다.
- 매출액 구성비는 매출건수/방문자 비율과 구분한다. 요일 표의 주중/주말 합계는
  개별 요일 분포에 포함하지 않는다. 선택 영역 이외의 지역 표로 대체하지 않는다.
- 표마다 기준 시점·범위와 근거 버튼을 제공한다. 시점이 없는 구성비에 월별
  추이 표의 최신 월이나 분석 생성일을 붙이지 않는다.
- 수치 표는 펼쳐서 볼 수 있으며 키보드로 선택 버튼과 출처를 사용할 수 있다.
  색만으로 값을 구분하지 않고 레이블과 비율을 함께 제공한다.
- 원문 비율이 없는 과거 브리프는 ‘최다 요일’ 등 확보된 관측값만 표시하며
  그 문구로 막대를 만들지 않는다. Quant 실패 원인 안내도 유지한다.

## 데이터 연결

[Issue #38](https://github.com/KT-SPoT/spot/issues/38)로 선택적 Brief 카드 확장을
추적한다. `read_quant_evidence`가 좌표·반경·업종·분석 생성일·대표 수치를 검사한
같은 실행의 보조자료에서만 요일/시간대와 매출액 비율을 추출한다. 기존 Scout
함수와 필수 v0.1 필드는 변경하지 않는다. Markdown에도 원래 비율이 보존된다.
화면용 추가 분포 카드는 기존 Critic 입력에 중복 추가하지 않는다. 기존 관측값과
인구 구성을 유지해 GPT 입력 크기·검토 요청이 시각화 작업 때문에 늘어나지 않게 한다.

프런트엔드 그래프는 기존 `app.js`와 `style.css`에 포함되어 새로고침하면 적용된다.
새 조사에서 확장 비율을 생성하려면 API 프로세스가 최신 Brief 코드를 로드해야 한다.
이미 완료된 작업의 내용은 소급 변경하지 않는다.

## 검증

`test_quant_distributions.py`는 동일 실행의 자료 선택, 결측·0·잘못된 수치,
매출액/매출건수 및 다른 지역 구분, 날짜 보존, Markdown 전달을 검사한다.
`test_quant_charts.js`와 `test_web_workspace.js`는 화면 전환, 원래 비율, 근거 창,
미확보 상태와 안전한 DOM 렌더링을 검사한다.

2026-10-01 저장된 명지국제신도시 조사와 같은 실행의 원문 보조자료를 재생해
실제 브라우저에서 3개 인구 모집단과 매출액 비율을 확인했다. 검증 중 새 Scout,
GPT 또는 소상공인365 호출은 없었다. 동래점은 당시 Quant 미확보이므로 이
자료로 대체하지 않는다.
