# Research Brief: 인구 구성과 관련 보도 묶음

API 실행에서도 Quant가 이미 수집한 상세분석 원문으로 성별·연령 비율과
지표 기준 시점을 연결한다. 이를 위해 provider를 다시 호출하지 않는다.
`run_quant_scout(request)`의 기존 출력은 유지하며 선택적인 내부
`evidence_sink` 콜백으로 원문을 graph state에 전달한다.
`ResearchBundle`과 HTTP 응답에는 이 원문을 포함하지 않는다.

원문은 기존 검증기로 좌표·반경·업종·분석 생성일·요약 지표를 대조한 뒤
사용한다. 유동·주거·직장 인구는 각각의 표로 표시한다. 성별·연령 표의
기준일을 별도 확보하지 못하면 `null`/확인 필요로 남긴다. 인구 추이 표의
최신 월이나 분석 생성일을 비율의 기준일로 대신하지 않는다.

Trend Scout의 후보와 출처는 그대로 유지하고 Brief 표시 단계에서 관련
보도를 묶는다. 같은 게시 날짜, 같은 선두 브랜드 표현, 따옴표로 표시된
고유명 공유를 사용한다. 요청 제품명과 일반 체험·제품 단어는 고유명에서
제외한다. 명시된 장소가 다르면 합치지 않으며 신호가 부족하면 각각 유지한다.
묶음의 대표 후보와 직접 비교하므로 연결이 약한 후보를 연쇄적으로 합치지 않는다.

이 분류는 동일 행사 여부를 확정하는 기능이 아니다. 표현·날짜가 다른
중복 보도를 놓칠 수 있고 동일 브랜드·고유명이 여러 행사에서 쓰일 수 있다.
따라서 `article_count`는 연결된 자료 수, `candidate_group_count`는 보도
묶음 수로 구분하며 독립 행사 수로 사용하지 않는다. 원문 출처와 관련
보도 제목·case ID를 모두 보존한다. 후보 패턴은 묶음이 2개 이상 남을 때만
표시하며, 한 행사의 여러 기사만으로 반복 패턴을 만들지 않는다.

검증: 합성 provider의 실제 API runner 테스트, 자료 불일치 검증,
날짜·장소·일반 제품 표현에 따른 분리, 단일 묶음의 패턴 제외, 출처 보존.
저장된 실제 자료 재생에서는 세 인구 모집단의 비율이 연결되고, 기존
트렌드 참고 기사 5개는 4건/1건의 두 묶음으로 표시됐다. 고유 출처 20개는
모두 보존됐으며 재생 중 새 provider 호출은 없었다.

Critic은 여전히 Mock이고 결과는 검토가 필요한 조사 초안이다.
