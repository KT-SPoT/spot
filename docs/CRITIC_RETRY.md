# 실제 규칙 Critic과 제한된 재조사

Graph는 Mock 대신 `run_critic`을 사용한다. 기존 R00–R08 검사기를 실제
CriticResult v0.1로 연결하며 source ID 연결, 계약, 게시·수집 날짜, 조회 기간,
중복 URL, 사례·패턴 수를 확인한다. 기존 preview CLI와 27개 합성 기준표는 유지한다.

의미·원문 진위·지역 차별성·캠페인 적합성을 승인하는 기능은 아직 없다.
기계적 검사가 통과해도 `manual_review`로 종료하며 자동 `pass`를 반환하지 않는다.
API의 `critic_is_mock`은 false이고 `critic_result`와 `retry_history`를 함께 반환한다.

## 재조사 정책

- 최초 Quant/Local 병렬 실행 → 맥락 → Trend → Merge → Critic.
- 일시적인 `PROVIDER_UNAVAILABLE` 또는 HTTP 500/502/503/504만 재조사한다.
- 최대 1라운드, 선택된 Scout만 각 1회 더 호출한다. `build_graph(max_retry_rounds=0)`으로 끌 수 있다.
- 계약·출처 오류, 빈 검색, `partial` 상태·경고만으로는 재호출하지 않는다.
- 401/403/429, 키 미설정, offline, parser 오류, 코드가 구체적이지 않은
  Quant 수집 오류는 자동 재조사하지 않는다. 재조사 불가 오류와 일시 오류가
  같은 모듈에 섞여 있어도 전체 모듈 재호출을 보류한다.
- 현재 Quant client의 일반 수집 오류는 원인 분류가 부족하므로 재조사 대상이 아니다.
- Mock 결과는 추가 provider 호출을 유발하지 않는다.
- 재조사 결과가 실패하거나 계약/기계적 근거 검증이 나빠지면 앞서 확보한
  사용 가능한 근거를 보존한다. 횟수는 이미 소비한 것으로 기록하고 더 호출하지 않는다.
- 재조사에 선정된 Trend는 갱신된 Quant/Local 맥락을 받는다. 상위 모듈만
  갱신됐고 Trend는 재실행하지 않았다면 경고를 남긴다. 숨겨진 의존성 갱신 호출은 하지 않는다.
- 실제 원문 대조 실패나 최신성/사례 다양성 부족을 해결하는 검색어 재설계는
  별도 정책과 의미 평가가 필요하므로 이번 자동 재조사 범위에 포함하지 않는다.

## 종료 및 근거 제외

안전하게 요약할 근거가 있으면 `manual_review`, 모두 미확보 또는 기계적
오류로 제외됐으면 `failed`다. 일시 오류가 재조사 대상이고 상한 전이면
`retry_required`로 라우팅한다. 상한 이후에는 Brief로 종료하며 미해결 사유를 남긴다.

`needs_fix`를 받은 모듈은 Brief에서 제외한다. Merge 원본과 Scout 출력은
보존하며 `checks.excluded_modules`로 제외 이유를 추적한다. API의 모듈 상태는
Scout 실행 결과이고 Critic·Brief 상태는 근거 검증 결과이므로 함께 확인해야 한다.
요청 전체 구조/기간 오류는 모든 모듈 근거를 제외한다.

예상 밖의 미처리 Scout 예외는 기존 API의 일반 실행 실패로 종료한다.
예외 본문은 반환하지 않고 자동 재시도도 하지 않는다.

## n8n 입구

기존 POST `/spot-research`는 조사 시작에 필요하다. 새 GET
`/spot-research-status?job_id=...`는 완료 결과를 읽는다. 시작과 조회를
분리해 요청 시간 초과를 피하며, n8n에는 Scout 재조사 loop를 추가하지 않는다.
작업 진행 중이면 동일 job_id를 조회하고 새 POST로 재시작하지 않는다.

합성 검증은 일시 오류 복구, 1회 상한, 인증/한도 오류의 재호출 금지,
기존 출처 보존, 갱신된 맥락 전달, 기준일 이후·끊어진 출처 제외,
의미 검토 미완료 유지, HTTP 응답의 인증 값 가림을 포함한다.
