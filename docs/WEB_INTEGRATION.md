# SPOT 웹 구현 입력·출력 계약

웹 구현 전의 연결 경로는 n8n 접수 → SPOT API의 비동기 조사 → n8n 상태 조회다.
웹은 조사 작업을 생성한 뒤 상태를 조회하며 긴 조사가 끝날 때까지 POST 연결을 유지하지 않는다.
Scout는 수집·기본 근거 확인, 규칙 Critic은 기계 검사, GPT Critic은 고객 연결·차별성과
응용 논리 검토를 맡는다. GPT 판단은 사실 인증이 아니며 실패해도 확보한 브리프를 보존한다.

## 웹 서버 경유

브라우저 → 같은 사이트의 웹 서버 → 인증된 n8n → 인증된 SPOT API 순서로 연결한다.
n8n 호출용 키와 SPOT 서버 키는 서버 측 설정에 보관한다. 브라우저 코드·번들·요청 본문에
넣지 않는다. 웹 로그인·접근 제한과 요청량 제한은 웹 서버에서 구현한다.
현재 저장소에는 웹 화면이나 이 웹 서버 중계 경로를 아직 구현하지 않았다.

제안하는 웹 서버 경계:

- `POST /api/research`: 아래 입력을 검증·정규화하고 n8n 접수 결과를 반환한다.
- `GET /api/research/{job_id}`: n8n 상태를 조회한다. 웹 사용자가 만든 작업인지 확인한다.
- request_id와 조사 기준일을 재접수 때 보존한다. 동일 입력은 동일 job으로 돌아오며,
  같은 request_id의 다른 입력은 409다. POST를 무작정 반복해 새 유료 작업을 만들지 않는다.

## 입력과 응답

매장 이름·주소, 조사 목적·상품은 필수다. 날짜 생략 시 한국 시간의 요청일을 사용한다.
좌표는 둘 다 제공하거나 둘 다 생략한다. 반경 기본 1000m, 조사 기간 기본 180일.
기간 0도 유효하다. 구체적인 필드와 제한은 `src/api/models.py`를 기준으로 한다.

```json
{
  "schema_version": "0.1",
  "request_id": "spot-web-demo-001",
  "store": {"name": "조사할 매장", "address": "실제 주소"},
  "campaign": {"purpose": "지역과 고객 구성에 맞는 체험 리서치", "product": "조사할 상품"},
  "research": {"radius_m": 1000, "lookback_days": 180}
}
```

접수 응답 202의 `job_id`를 저장하고 약 5초 간격으로 GET을 조회한다.
`queued`·`running`은 진행 중, `completed`는 그래프 실행 완료, `failed`는 실행 실패다.
완료된 조사에도 근거 부족·Critic 미완료가 있을 수 있으므로 작업 완료와 품질 상태를 구분한다.

- `result.research_brief`: 구조화된 브리프. 기존 공통 v0.1 필드를 유지한다.
- `result.research_brief_markdown`: 읽을 수 있는 브리프. 웹 Markdown 표시는 HTML을 차단·정제한다.
- `result.research_brief.research_review`: 선택적 연구 Critic 결과와 사례별 보완 방향.
  `performed`·`code`를 보고 완료/미완료를 구분한다.
- `result.module_status`: Scout별 결과. partial 하나만으로 전체를 실패 처리하지 않는다.

## 화면에 표시할 오류

| 상태 | 안내·처리 |
|---|---|
| 401 / 403 | 연결 인증 설정 확인. SPOT API는 401, n8n Header Auth는 403을 반환한다. 키 값은 화면에 표시하지 않는다. |
| 422 | 누락·잘못된 입력 항목을 표시한다. |
| 409 | 같은 요청 번호의 다른 입력. 수정 제출은 새 요청 번호로 구분한다. |
| 429 | 작업 대기열이 가득 참. Retry-After를 따르고 새 POST를 반복하지 않는다. |
| 404 | 작업 없음·만료. 재조사 여부를 사용자가 결정한다. |
| 503 | SPOT 서버·개발 터널 연결 불가. GET 조회는 나중에 다시 시도한다. |
| failed | 안정된 error.code와 재조사 선택을 표시한다. 제공자 예외·키는 노출하지 않는다. |

## 현재 MVP의 운영 범위

SPOT API는 단일 조사 worker, 진행·대기 최대 4개, 기록 최대 32개다.
기록은 기본 1시간 또는 서버 재시작 때 사라진다. 현재 GET은 소유자별 권한 분리를
제공하지 않으므로 웹 서버에서 사용자별 작업 소유권을 관리해야 한다.
영구 작업 저장·복수 서버·취소는 후속 범위다. 임시 개발 터널은 PC와 터널이 실행 중일 때만
접근 가능하며 운영 배포를 대체하지 않는다. Cloud 계정 체험 만료도 별도 확인이 필요하다.
