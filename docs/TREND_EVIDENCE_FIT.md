# 전국 사례 원문 확인과 고객층 연결 — 2026-10-02

## 이번 단계

네이버 검색으로 선정한 전국·다업종 참고 후보에서 기사 제목과 본문 참여 방식 표현을
대조하고, Quant의 모집단별 관측값에 연결한 조사 질문을 만든다.
소상공인365의 성별·연령·시간대 관측값은 정량 기준으로 유지한다.
관측된 구성만으로 행사 선호, 구매 의향, 성별×연령 교차 분포를 추정하지 않는다.

`SPOT_TREND_DETAIL_MODE=article`을 설정하면 선택된 참고 슬롯 중 최대 5개의 뉴스
원문에 접근한다. 기본값은 `off`이며 offline 모드에서는 원문 접근도 하지 않는다.
YouTube 원문은 이 경로에서 처리하지 않는다. 요청당 기사 8초 제한, 최대 1.5MB,
최대 리다이렉트 3회와 공개 HTTP(S) 주소 검사는 기존 공통 기사 조회기를 재사용한다.
최대 5개를 순차 조회하므로 원문 접근이 느리면 전체 연구 시간도 늘어날 수 있다.

## 출력 해석

- `case_detail`: 제목 일치, 원문 날짜 범위, 본문 참여 방식 키워드와 출처 ID.
  `text_corroborated`는 본문 표현 대조이며 행사 개최나 성과 인증이 아니다.
  원문 날짜가 없으면 `null`을 보존한다. 검색 제공일을 원문 게시일로 대체하지 않는다.
- 방문객 수가 본문에 있으면 집계 주장으로, ‘인기·큰 호응’은 홍보 표현으로 구분한다.
  예정·목표 수치를 실적에 넣지 않는다. 행사 귀속·측정 방법·연령별 반응은 추가 확인 대상이다.
- `audience_fit`: 실제 Quant 출처가 있는 유동·매출·주거·직장 자료를 분리한
  `research_hypothesis`. 미션, 촬영, 수집, 직접 체험 등 확인한 방식에 따라
  휴대폰 응용 가설과 인터뷰 질문을 만든다. 원문 확인을 끄면 검색 메타데이터 기반임을 표시한다.
- Brief는 Quant 맥락 출처와 Trend 참여 방식 출처를 모두 연결할 수 있는 가설만 표시한다.
  Semantic Critic 입력에도 원문 대조 결과와 가설을 포함하되 자동 유료 호출은 켜지 않는다.

## 실제 자료 검증

이전 실제 네이버 결과와 Quant·Local 자료를 재사용했다. 이번 단계의 새 검색·YouTube·GPT
호출은 0회이며, 선정 기사 5개의 웹 본문에 접근했다. 코드 수정 후 출력 재생에는 저장된
본문 확인 결과를 재사용해 기사 추가 조회도 하지 않았다. 모든 Scout의 당일 재수집 결과는 아니다.

5건 모두 제목·본문 표현 대조를 통과했고, 모집단 4개씩 총 20개 조사 질문을 생성했다.
확인한 본문에서 방문 실적·호응 표현을 추출하지 못했다. 이 결과로 해당 고객층이

자료나 해당 상권 고객 인터뷰로 참여 방식별 호응 가설을 비교하는 것이다.

`result.json`에 저장했으며 Git에 포함하지 않는다. 운영 서비스·n8n 배포는 이번 단계에 포함하지 않았다.
