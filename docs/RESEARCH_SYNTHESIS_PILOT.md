# 기본 해석 + 추가 인사이트 검증

2026-10-07 사용자 결정: 일반적이지만 기획에 도움이 되는 결과를 인정한다. 차별성은 채택 조건이 아니라 추가로 찾을 가치다. 지역마다 다른 결과를 만들기 위해 해석을 억지로 바꾸지 않는다.

## Critic 기준

| 결과 | 처리 |
| --- | --- |
| 관측을 이해하기 쉽게 정리한 일반적 해석 | 기본 해석으로 유지 |
| 보도된 참여 방식에서 얻을 수 있는 일반적인 기획 참고 | 연결 설명이 타당하면 유지 |
| 인구·매출 또는 지역 변화의 관계가 구체적인 검토 선택지를 만드는 해석 | 추가 인사이트로 구분 |
| 숫자·모집단·사업 단계가 틀리거나 관측에 없는 선호·효과를 사실로 주장 | 해당 문장이나 연결을 제외 |
| 사례의 연결 설명이 약함 | 사례는 전국 참고로 남기고 해당 연결만 제외 |

`differentiation=generic`은 실패 판정이 아니다. 기존 Research Critic의 `useful`은 `transfer_logic=clear`, `overclaim=clear`이면 가능하며, 지역 적합성이나 독창성을 필수 조건으로 삼지 않는다. Brief·기획 단서·Trend 화면에서도 차별성이 약하다는 이유만으로 타당한 연결을 지우지 않는다. 일반적인 연결은 화면에서 기본 기획 참고로 표시한다.

숫자가 많은 연령을 실제 점포 고객이라고 확정하거나, 성별과 연령의 별도 표를 하나의 교차 고객군으로 만드는 오류는 계속 통제한다. 전국 사례나 타 업종 사례라는 이유, 고객 반응 조사를 하지 않았다는 이유만으로 탐색 질문을 탈락시키지 않는다. Critic은 기획 질문의 효과를 입증하는 심사자가 아니다.

## 저장 자료로 확인한 예시

10월 4일 저장한 동래점·광화문중앙점의 실제 조사 결과를 재해석했다. 새로운 Quant·Local·Trend 검색은 실행하지 않았다. 소상공인365 값은 선택 영역·업종의 집계이며 개별 KT 점포의 거래 기록이 아니다.

| 지역 | 기본으로 제공할 관측 | 함께 읽었을 때의 추가 포인트 |
| --- | --- | --- |
| 동래점 | 매출액 구성에서 60대 이상 58.3%, 토요일 27.6%가 각각 가장 높음 | 평일 유동 비중은 14.9~15.1%로 비슷하지만 매출 요일 구성은 토요일이 가장 큼. 평일 안내 접점과 토요일 체험 접점을 별도로 검토할 수 있음 |
| 광화문중앙점 | 매출액 구성에서 20대 36.1%, 14~18시 67.5%가 각각 가장 높음 | 유동인구의 최다 연령은 60대 이상 24%이고 매출액의 최다 연령은 20대임. 주변 인구 설명과 홍보의 우선 검토 연령을 구분해 읽을 수 있음 |

관측 출처: [소상공인365](https://bigdata.sbiz.or.kr/). 표별 모집단·기준 기간을 유지하며 서로 다른 구성비를 빼서 전환율로 해석하지 않는다.

## 구현과 검증 범위

- `src/brief/synthesis.py`: 관측 ID와 출처를 보존한 해석 생성 및 별도 Critic 검토. 하나의 관측으로도 기본 해석을 생성할 수 있다. generic 또는 모호한 기획 질문이라는 이유만으로 뒷받침되는 해석을 삭제하지 않는다.
- `src/evaluate_regional_synthesis.py`: 저장된 Brief 비교용 CLI. 생성과 검토를 분리하고 입력·후보·검토·채택 결과를 기록한다. 저장 자료에 이름만 바꿔도 입력의 관측이 바뀌지 않는지 테스트한다.
- 기존 Critic·Brief·기획 단서·Trend 화면: 일반적인 연결을 유지하는 기준을 일치시켰다. PDF 본문에서 Critic의 응용 보완 건수 표시를 제거했다. 진단은 구조화된 결과에 남는다.

마지막 자동 생성 검증에서 두 지역 모두 3개 해석을 생성·채택했다. 지역당 생성 1회와 Critic 1회를 실행했다. 별도로 편집한 초안은 지역당 Critic 1회로 검토해 동래 1개, 광화문 2개를 채택했다. 편집한 초안의 결과를 자동 생성 성능으로 계산하지 않는다. 이 횟수는 마지막 검증 실행의 기록이며 전체 실험의 누적 호출 수가 아니다.

자동 생성 비교는 `output/synthesis-automatic-baseline-plus/comparison.md`, 편집 초안 비교는 `output/synthesis-baseline-plus/comparison.md`에 있다. 평가 JSON에는 제외 사유도 기록한다. 키·토큰·원본 응답 예외는 출력하지 않는다.

이번 두 지역의 자동 생성 결과에는 전국 사례와의 추가 연결이 채택되지 않았다. 통계 해석이 개선됐다는 것과 Local·Trend를 통합한 기획 연결이 완성됐다는 것은 구분해야 한다. Local 관측과 참여 행동이 추가 해석을 만드는지는 후속 검증 대상으로 남긴다. 특별한 연결을 만들기 위해 기존 사례를 억지로 붙이지 않는다.

이 문단까지는 초기 통계 해석 검증 기록이다. 이후 Local·Trend 연결 단계와 선택적인 그래프 실행 경로를 추가했다. 아래 후속 기록은 저장 자료 실험과 실행 경로의 구현을 설명한다. 운영 적용 여부는 마지막의 날짜별 기록을 기준으로 한다. 자동 결과는 의미 검토를 계속 필요로 하며, Critic 통과를 선호·성과 인증으로 사용하지 않는다.

## 실행

```bash
# 공개 관측 입력만 준비. API 호출 없음.
python -m src.evaluate_regional_synthesis

# 저장 Brief마다 생성 1회 + Critic 1회. Scout 재조회 없음.
python -m src.evaluate_regional_synthesis --live --output-dir output/synthesis-pilot
```

관련 Python 회귀 테스트 86개와 Trend 화면의 Node 검증이 통과했다. 일반적인 결과 보존, 약한 연결만 제거하기, 수치·교차 고객군 오류 차단, 기획 단서의 빈 상품·인력 항목, PDF 출처 링크와 진단 문구 분리, 추가 Scout 호출 방지를 검사했다.

필수 SpotRequest / ScoutResult / ResearchBrief v0.1 필드는 유지한다. 초기 파일럿에서 비교 파일에 담았던 `regional_synthesis` 진단과 `research_implications[].contribution`은 후속 선택적 실행 경로에서도 사용하는 메타데이터다. 공통 Notion 계약에 반영됐다고 간주하지 않는다.

## 후속: Local 맥락과 실제 참여 방식 연결

통계 해석 생성 단계에서 Local·Trend를 한꺼번에 읽으라고 하면 통계 요약이 대부분의 자리를 차지했다. 이에 기존 상권 해석을 보존한 뒤 Local 참고와 사례 연결을 따로 작성·검토하는 단계를 추가했다.

모델은 검토된 `planning_lens_id`와 실제 `action_id`를 선택한다. 그 해석의 출처 ID는 코드가 자동 연결한다. Critic에는 각 후보에 붙인 표·기사·참여 행동만 전달하며 다른 후보의 표로 빠진 근거를 보충하지 않는다. Local 보도 날짜는 제목·관측란에 붙인다. 적용 범위 문구는 기존 검토된 해석의 범위를 재사용하며 새로운 고객 행동 설명을 생성하지 않는다.

마지막 검증에서는 각 지역의 기존 해석 3개를 유지하고 Local 참고 1개와 직접 체험 연결 1개를 추가했다.

| 지역 | Local 참고 | Trend 연결의 검토 질문 |
| --- | --- | --- |
| 동래 | 2026-05-18 내성지하차도 명륜동·교대 방향 통행 재개 보도를 당시의 방문 안내 맥락으로 읽음 | 오후 시간대 구성을 참고해 설명만 듣는 방식과 직접 사용·비교하는 방식을 어떻게 구성할지 검토 |
| 광화문 | 2026-10-03 새문안로·자하문로 행진 계획 보도를 해당 행사일의 방문 안내 맥락으로 읽음 | 고른 평일 유동과 금요일 매출 구성을 참고해 평일 안내와 금요일 직접 체험 접점을 구분할지 검토 |

두 지역은 같은 지스타 직접 체험 보도를 참고했다. 이는 전국 참고 사례로 정상적인 결과이며 다른 사례를 억지로 선택하지 않았다. 특정 연령이 게임 행사를 좋아한다고 판단한 결과가 아니다. Local 교통 보도와 게임 체험을 하나의 인과관계로 묶지도 않았다.

결과: `output/local-trend-connections-reviewed/comparison.md`. 이전 초안·검토는 별도 디렉터리에 보존한다. 초안에서 출처에 붙이지 않은 시간대, 효과 주장, 과거 사건의 현재 활용 표현이 발견되어 출처 선택 구조와 범위 표시를 보강했다. Critic의 통과율만으로 품질을 판단하지 않고 실제 문장을 읽어 확인했다. 최종 범위 표시 검토는 지역당 Critic 1회이며 새 생성·Scout 조회 없이 앞서 생성한 초안을 재사용했다. 이는 전체 실험의 누적 호출 수가 아니다.

Local·Trend 연결은 읽기 가능한 기획 참고 수준으로 개선됐다. 현재 두 지역의 Local 자료는 과거 교통 보도이고 구체적인 생활 장면 자료의 범위는 좁다. 생동감 있는 지역 기회나 다양한 전국 사례가 충분히 발굴됐다고 단정하지 않는다. 새 검색과 영상 조회도 이번 검증에서 실행하지 않았다.

## 조사 흐름에서 선택적으로 실행하기

`src/brief/pipeline.py`를 기존 LangGraph의 Brief 단계에 연결했다. 기본값은 off이며 다음 설정을 모두 만족할 때 실행한다.

```dotenv
SPOT_BRIEF_SYNTHESIS=connections
SPOT_SCOUT_MODE=live
SPOT_SEMANTIC_MODE=shadow
SPOT_CRITIC_PROFILE=research
```

상권 해석 생성·검토 각 1회, 추가 연결 생성·검토 각 1회로 최대 4회 호출한다. 이 모드에서는 이전 사례 Critic을 중복 실행하지 않는다. 추가 생성이 비어 있거나 실패하면 기존 상권 해석을 보존하며, 상권 해석 자체가 실패하면 원래 Brief를 보존한다. off·offline·명시적인 semantic 비활성화에서는 추가 모델을 호출하지 않는다. Scout 재검색·재시도 정책은 유지한다.

`regional_synthesis`, `connection_synthesis`와 `research_implications[].contribution`은 선택적 메타데이터이며 필수 v0.1 필드는 바꾸지 않는다. 기본값 off는 유지하고 운영 서버에서는 명시적으로 활성화한다. 새 검색어 선정까지 앞 단계의 의미 해석을 전달하는 경로는 이번 변경에 포함되지 않는다.

```bash
# 저장된 상권 검토 재사용: 새 연결 생성 1회 + 검토 1회씩
python -m src.evaluate_regional_synthesis --live --connections \
  --base-evaluation-dir output/synthesis-automatic-baseline-plus \
  --output-dir output/local-trend-connections
```

## 2026-10-07: 서울 운영 적용 및 새 조사

서울 서버에 선택적 `connections` 경로를 활성화했다. 기존 n8n Cloud 접수·조회 URL, Header Auth, 웹 로그인은 유지했다. API·웹 이미지와 변경 소스·설정은 교체 전 백업하며, 키는 출력하거나 전송 파일에 포함하지 않는다.

동래·광화문을 실제 n8n 경로로 각각 새 조사했다. 두 지역 모두 Quant 성공, Local·Trend 부분 성공이며 상권 기본 해석 3개와 날짜를 표시한 Local 참고 1개를 채택했다. 지역당 추가 해석 생성·검토 총 4회, 이 두 조사 합계 8회 GPT 호출이다. 유동인구 연령과 매출액 연령이 다를 때 구별하는 문장을 확인했다. YouTube 결과는 광화문 10건, 동래 0건이었다. 수집 완료 상태를 영상 확보 건수와 혼동하지 않는다.

이 최초 실행에서는 Trend 연결 초안 자체가 0개였다. Critic의 일괄 거절이 원인이 아니었다. 기사에서 실제 체험을 말하는 `직접 보고 체험`, `제품을 직접 경험`이 행동 인식 규칙에서 누락되어 후보 입력이 비어 있었다. 실제 행동 표현을 추가하고 권고 문장이 실제 개최·참여 행동으로 바뀌지 않도록 회귀 검증을 추가했다. 수집한 두 Brief를 다시 검토하는 후속 실행은 별도로 기록하며 새 Scout 조회로 계산하지 않는다.

Local 참고에는 과거 교통·집회 보도가 포함된다. 날짜를 표시한 참고이지 현재의 생활 변화나 매장 방문 증가를 확인한 결과가 아니다. 특별한 지역 기회가 충분히 발굴됐다는 뜻으로 통과 건수를 사용하지 않는다.

표현 인식 수정 후 같은 새 조사 자료를 재검토한 결과, 행동 후보는 동래 1개·광화문 2개로 복구됐다.
기본 해석 3개씩을 유지하고 추가 단계에서 동래 2개(Local 1·Trend 1), 광화문 3개(Local 1·Trend 2)를 채택했다.
지역당 생성·검토 4회씩 총 8회 GPT 호출을 추가했으며 Scout 재조회는 0회다.
이는 수정본에서 저장된 자료의 자동 생성·검토 결과다. 수정 후 새 n8n 조사를 또 실행한 결과로 계산하지 않는다.
키·원본 예외는 출력하지 않았으며, 관련 회귀 테스트 33개와 이미지 컴파일·그래프 import·HTTPS health가 통과했다.

위 채택 건수는 중간 `connections-v2`의 결과다. 실제 문장 점검에서는 지난 행진의 현재 활용,
비중만으로 홍보에 유리하다는 표현, 원문에 없는 매장 고객 연령 일치가 나타났다.
Critic 통과 건수만으로 이 문장들의 품질을 보증하지 않는다.
`connections-v3`에서는 시간 구간의 임의 합치기, 긍정 효과·점포 고객·반경 단정,
보도에 없는 설명 대비 체험 비교를 확인하며 과거 교통·집회 기록의 질문은 보도 참고로 한정한다.
부적절한 후보 하나가 다른 유용한 기본 해석을 지우지 않도록 후보별로 처리한다.
기획자가 효과를 비교해볼 질문과 효과가 입증됐다는 진술을 구별하는 기준은 유지한다.
최종 관련 Python 회귀 테스트 82개와 Trend 화면 Node 검증, 이미지 import, HTTPS health가 통과했다.

최종 `connections-v3`의 저장 자료 재검토도 기본 해석 3개씩, 동래 Local 1·Trend 1,
광화문 Local 1·Trend 2를 채택했다. 이 마지막 재검토는 지역당 4회, 합계 8회 GPT 호출과
Scout 0회다. 이번 운영 검증·두 차례 재검토 전체의 추가 GPT 호출은 24회다.
최종 요약: `output/deployment/connections-final-summary.json`.
첫 두 n8n 새 조사의 요약은 `output/deployment/connections-live-inspection.json`에 별도로 보존한다.
수정 후 두 차례 재검토를 새 조사 성능으로 합산하지 않는다.

최종 생성 문장에서도 Local은 과거 사건의 방문 안내 참고이고, Trend는 직접 체험과 설명 안내를
비교하는 기본적인 질문이 주를 이룬다. 유용한 기본 결과가 연결된 것은 확인했지만,
특별한 생활 변화·지역 기회나 행사별 세부 참여 과제까지 충분히 발굴했다고 설명하지 않는다.
방문자 연령의 일치·행사 호응·매출 효과가 확인됐다는 의미도 아니다.
