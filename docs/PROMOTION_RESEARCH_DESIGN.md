# 제품·매장 중심 홍보 리서치 설계

## 제품의 목적

SPoT은 특정 매장에서 제품·서비스를 알리기 전에 고객 가능성과 사용 가치,
지역·시기 맥락을 조사하고 서로 다른 홍보 방향의 근거를 제공한다.
출점 후보지 발굴·추천·입지 순위와 실행 예산·인력·혜택 결정은 범위에서 제외한다.
후보지 기능 제거와 입력 정리에 이어, 공통·제품/질문·기준월 행사 검색 3개와 검색 이유 표시를 구현했다.
공식 제품 자료·고객 사용 조사와 전국 일정 수집 등 아래 나머지 조사 흐름은 후속 구현 설계다.
현재 범위는 [Trend 보드와 내보내기](TREND_BOARD_AND_EXPORTS.md)를 확인한다.

## 입력의 역할

| 입력 | 역할 | 결과에서 보여줄 연결 |
| --- | --- | --- |
| 홍보할 제품·서비스 또는 제품군 | 조사 대상; 고객층을 미리 지정하지 않음 | 확인된 사용 가치, 고객 관심·사용 자료, 응용에 사용한 기능 |
| 매장 이름·검색한 주소·좌표 | 조사할 지역 | 공공 인구·상권 구성, 직접 지역 변화·주변 맥락 |
| 특히 알아보고 싶은 점 — 선택 | 답해야 할 질문 | 질문별 발견·근거·미확보 항목과 홍보 방향 |
| 관심 고객층 — 선택 | 사용자의 가정 | 실제 고객 자료와 부합하는지; 고정된 타깃으로 확정하지 않음 |
| 자료 기준일·조회 기간·반경 | 수집 범위 | 출처별 시점·범위 표시 |

질문을 비운 웹 요청은 기존 `campaign.purpose`에
`제품·지역 맥락을 연결한 홍보 근거 탐색`을 넣는다. 제품과 목적의 필수 API
문자열 계약은 변경하지 않는다. 활용 예정 시기는 자료 기준일과 별개이며,
추가하려면 먼저 공유 입력 계약의 확장안을 검토한다.

## 제품명은 이렇게 조사한다 — 후속 구현

1. 정확한 모델과 제품군을 구분하고 공식 제품 자료에서 기능·사용 가치를 확보한다.
   이름만으로 기능을 추측하지 않으며 확인되지 않은 기능은 미확보로 둔다.
2. 공개된 사용·관심·구매 조사 자료가 있으면 표본·기간·제품 범위를 보존한다.
   제품군의 사용 조사를 특정 모델의 선호나 구매 의향으로 바꾸지 않는다.
3. 제품의 확인된 사용 가치와 지역의 관측 맥락을 연결해 탐색 가설을 만든다.
   특정 나이가 많다는 이유만으로 호응을 확정하지 않는다.
4. 제품을 바꾸면 달라진 사용 가치와 조사 질문을 설명한다. 새 제품명이 들어간
   동일 문장만 반복하면 제품 연결이 부족한 것으로 검토한다.

## 조사 질문은 이렇게 활용한다 — 후속 구현

- 사용자의 질문과 기본 질문(어떤 사용 가치·고객 상황·지역 연결점을 주목할까?)에서
  근거를 찾을 수 있는 2~3개 질문을 만든다. 계획·실행 지시는 조사 질문으로 바꾼다.
- Quant와 Local의 공통 관측값은 유지한다. 목적마다 수치를 달리 해석해 만들어내지 않는다.
- Trend는 공통 탐색·질문 기반 탐색·확장 탐색으로 검색 3개를 구성한다.
  업종이나 세대의 취향을 고정하지 않고 검색 이유와 상류 근거를 기록한다.
- 제품의 관심 세대 질문에는 제품/제품군의 실제 고객 자료를 먼저 찾는다.
  전국 체험 사례만으로 해당 제품의 연령별 반응을 판단하지 않는다.
- 전국 일정·시즌 맥락은 별도 축으로 검토한다. 예정 일정과 과거 사례를 구분한다.
  전국 이벤트가 있어도 해당 지역의 수요나 방문 효과를 자동으로 확정하지 않는다.

## 브리프와 Critic의 연결 — 후속 구현

브리프는 제품의 확인된 사용 가치, 지역 고객 구성, 시기별 맥락, 고객 가능성,
서로 다른 홍보 방향 2~3개, 방향별 근거·반대 근거·미확보 항목을 제공한다.
실제 반응 자료 / 관측된 구성 / 탐색 가설을 구분하며 임의 적합도 점수를 만들지 않는다.

Critic은 각 방향이 질문에 답하는지, 제품 가치를 실제로 활용하는지, 매장명만
바꿔도 같은 제안인지, 방향 간 차이가 있는지, 선호·효과를 과장했는지 검토한다.
비판을 받으면 기존 근거 안에서 초안을 1회 수정한다. 부족한 근거 때문에
추가 검색이 필요할 때만 정해진 호출 예산 내에서 실행하며 무한 반복하지 않는다.

## 현재 구현과의 차이

현재 실제 Trend 검색어는 여전히 게임·음식 팝업·지역 축제 3개다. 제품은 응용
가설과 GPT 입력 등에 사용되고 목적은 GPT 검토 맥락으로 전달된다. 제품 가치와
고객 관심 자료를 별도로 수집하는 단계, 질문별 동적 검색, Critic 후 초안 수정,
향후 활용 시기를 기준으로 한 전국 일정 수집은 아직 없다.
입력창 변경이 이 기능들을 구현했다고 표시하거나 암시하지 않는다.

후속 검증은 위치를 고정하고 제품·질문을 각각 바꾸는 비교, 동일 제품의
서로 다른 지역 비교, 질문 없이 실행하는 기본 경로를 포함한다. 결과가 반드시
달라야 하는 것이 아니라 어떤 근거 때문에 달라졌거나 같았는지 설명할 수 있어야 한다.
