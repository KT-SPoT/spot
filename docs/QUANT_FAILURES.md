# Quant 미확보 원인 표시

2026-10-03 동래점의 실제 입력(명륜동 386, 반경 1000m)으로 Quant만 재조회한
결과, 소상공인365 `/gis/openApi/detail` 단계에서 HTTP 503을 받았다. 카카오 매장
검색은 성공했다. 당시 실행의 공개 결과에는 원래 Scout 오류가 보존되지 않아
이 재조회 결과를 과거 실행의 확정 원인으로 소급하지 않는다.

실패 Scout의 알려진 오류를 기존 ResearchBrief v0.1 `needs_manual_check` 문자열에
안내한다. Quant 세부 화면은 지표가 없을 때 해당 안내를 표시한다. HTTP 5xx는
일시적 제공 서버 오류, 401/403은 인증·권한 확인, 429는 호출 제한으로 구분한다.
알 수 없는 오류는 연결 실패 또는 일반 실패로 표시하고 원문 예외를 전달하지 않는다.
필수/선택 JSON 필드, 재시도 정책, 확보 자료의 근거 처리 방식은 변경하지 않는다.

수집기는 오류 URL, 응답 본문, 네트워크 예외 문자열을 결과에 복사하지 않는다.
고정 단계명과 HTTP 상태만 전달한다. 실패한 Quant의 수치를 추정하거나 다른 지역
자료로 대체하지 않으며 Local/Trend 자료는 브리프에 보존한다.

서비스 복구 후 새 조사가 필요하다. 이미 완료된 작업은 다시 조회해도 Scout를
재실행하지 않는다. 코드 수정 전 완료된 작업에는 새 오류 안내가 소급 적용되지 않는다.
