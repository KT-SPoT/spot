# 고객층 근거를 읽는 Trend 응용 질문 — 2026-10-03

추적: [Issue #34](https://github.com/KT-SPoT/spot/issues/34),
기존 비교: [Trend 고객층 검증](TREND_AUDIENCE_VALIDATION.md).

## 달라진 동작

전국·다업종 탐색과 참고 후보 선정은 유지한다. 선정된 사례의 매장 응용 단계는
이제 Quant의 전체 분포·모집단·최다 요일/시간과 Local 맥락을 읽는다.
검색의 참여 방식보다 기사 본문 대조로 확보한 참여 방식을 우선 사용한다.
선정 이유에는 검색 후보로 참고하는 이유와 **선정 후 응용 검토에 연결한 근거**를
구분해서 표시한다. 고객층 적합성을 증명했다거나 점수에 반영한 것처럼 표현하지 않는다.

- 연령 비중 합계가 99~101%인 두 항목 이상의 표에서 최대 비중이 50% 이상이면
  주요 연령대의 사용 장면과 나머지 연령대의 선택 가능성을 함께 조사한다.
  그렇지 않으면 여러 사용 장면을 직접 고르는 비교 방식을 조사한다.
- 남녀 비중 합계가 99~101%이고 최대 비중이 60% 이상이면 비중이 큰 성별만으로
  해석해도 되는지 검토한다. 양쪽 구성이 비슷하면 특정 성별에 좁히지 않는
  사용 장면 선택 방식을 조사한다. 성별과 업종·취향을 연결하지 않는다.
- 두 임계값은 질문을 구분하는 설계 규칙이다. 통계적 유의성·흥행 가능성 기준이 아니다.
  누락·부분 분포·잘못된 수치에서는 집중/분산을 판단하지 않는다.
- 유동·매출의 최다 요일/시간이 다르면 관심을 끄는 도입 체험과 제품 가치를
  비교하는 체험을 서로 다른 방문 상황에서 검토한다. 같은 경우에는 이어지는
  방문 흐름을 가설로 검토한다. 체류 시간·방문 목적을 추정하지 않는다.
  알려진 기준 기간이 다르면 한 방문 흐름으로 묶지 않고, 기간 미확보는 표시한다.
- 교통 맥락은 첫 비교 과제를 발견·이해하는 과정에, 주거 맥락은 생활 속 사용
  장면 선택에 연결한다. Local의 출처·주변/배경 역할·예정 상태를 유지하며
  실제 점포 수요 증가로 바꾸지 않는다.

예를 들어 같은 축제의 미션 구조도 유동·매출 최다 시간대가 다르면
“관심을 끄는 도입 체험과 제품 가치 비교를 다른 방문 상황에서 검토할 수 있을까?”가
붙고, 최다 시간대가 같으면 “도입 체험에서 제품 가치 비교까지 같은 방문 흐름으로
연결할 수 있을까?”가 붙는다. 각 질문은 확인된 체험 구조와 함께 제시한다.

성별·연령 이름만 바뀌고 선호 근거나 분포·시간·지역 조건은 같다면 같은 질문이
타당할 수 있다. `20대=게임`, `여성=뷰티`를 적용하지 않으며, 별개의 연령·성별
분포를 `40대 남성 고객` 같은 교차 집단으로 바꾸지 않는다. 매출 비중은 구매자 수가 아니다.

## 출력과 연결

`SpotRequest` 및 공통 `ScoutResult v0.1`은 유지한다.
선정 사례의 `audience_fit.question_basis`에는 질문을 만든 축·규칙·관측·질문과
사용한 Quant/Local 출처가 들어간다. 응용 가설은 기존 `kind=research_question`,
`mechanism`, `statement` 형태를 유지한다. 누락 출처가 있는 해석은 Brief에서 제외한다.

웹의 Trend 카드에는 응용 질문이 표시되고, **근거 보기**에서 선정 이유 및
유동·주거·직장·매출 비중별 응용 검토를 펼칠 수 있다. Markdown에도 모두 전달한다.
GPT Critic 입력에서는 중복 진단·관측 문장을 줄이고, 실제 응용 질문과 모집단별
근거 연결을 유지한다. 기존 입력 크기 제한과 호출 정책은 유지한다.

## 재검증 결과

2026-10-02 기준 저장 실제 뉴스 600행과 저장 기사 대조를 재생했다.
20/40/60대 이상 × 주요 성별 남/여의 6조건에서는 같은 참고 사례 5건을 유지했고
응용 문장·조사 질문도 동일했다. 이 입력은 전체 분포가 없는 이름 변경 실험이다.
평가기의 `partial_audience_conditioning` 판정은 그대로 남긴다.

추가 합성 대조는 성별·연령 이름을 고정하고 근거 축만 하나씩 바꿨다.

| 변경 축 | 공통 사례 | 응용 문장 변경 | 조사 질문 변경 |
|---|---:|---:|---:|
| 연령 분포: 분산 ↔ 집중 | 5 | 5 | 5 |
| 성별 비중: 55/45 ↔ 75/25 | 5 | 5 | 5 |
| 유동·매출 최다 시간대: 일치 ↔ 차이 | 5 | 5 | 5 |
| 모집단: 유동 ↔ 주거 | 5 | 5 | 5 |
| 주변 입주 예정 맥락: 없음 ↔ 있음 | 5 | 5 | 5 |

선정 집합·순서·검색어·점수는 유지했다. 표기된 관측만 바뀌는 경우를 실질적 질문
변화로 세지 않는다. 전체 실제 고객층 4종을 전달한 재생 결과에서도 사례 5건의
고객층 연결 가설 20개가 Brief에 남았고 GPT 검토 입력은 기존 제한 안에 들어갔다.

새 네이버·YouTube·GPT·기사 호출은 0회다. 합성 대조는 실제 점포의 관측을 수정한
것이 아니며 오늘의 새로운 트렌드 조사, GPT의 품질 평가, 실제 고객 선호 검증은 아니다.
출력 변화는 데이터 반영의 증거이며 아이디어의 참신함·효과를 인증하지 않는다.

```bash
python -m src.evaluation.trend_audience \
  --bundle .venv/verification/trend-evidence-fit/result.json \
  --cache .venv/verification/nationwide-trend-live/search_cache.json \
  --output .venv/verification/trend-audience-improved
python -m unittest tests.test_trend_transfer -v
```

원본 자료와 상세 비교는 ignored 로컬 경로에 보관한다. API 키·원본 HTML·credential
URL은 문서에 넣지 않는다. 단독 Trend 호출과 고객층 미확보 입력은 기존 참여 방식
질문으로 동작하며, 누락 캐시를 새 API 호출로 대체하지 않는다.
