# 매장 중심 입력·Local·Critic·실제 지역 Trend 비교

2026-10-04 사용자 승인에 따라 구현하고 실제 자료로 점검했다.
추적: [Issue #44](https://github.com/KT-SPoT/spot/issues/44).
기존 [개선 전 진단](STATUS_AUDIT_2026_10_04.md)의 후속 결과이며,
공통 Notion 문서가 이미 동기화됐다는 의미는 아니다.

## 입력과 출력 경계

새 웹 입력에서 제품명·자유 조사 목적·관심 고객층을 제거했다.
매장/위치를 선택하고 기준일·기간·반경만 조정한다. API는 campaign 생략을
허용하고 product/target_hint=null, 목적=매장 지역·고객 맥락 리서치로 정규화한다.
가짜 제품명을 채우지 않는다. 기존 제품·목적 포함 요청은 호환한다.
n8n 내보내기 normalization도 campaign 생략을 허용한다.

신규 Trend 검색은 `팝업`, `오프라인 체험 행사`, `2026 10월 축제`다.
기준월은 요청 기준일을 읽는다. 연령·성별로 특정 업종 취향을 단정하지 않는다.
제품·강조 가치·기획 목적은 브리프 이후 흥부장 요청에 사용자가 추가한다.
PDF 및 흥부장 출력도 제품 미정 상태를 그대로 보존한다.

## Local 개선

- 질문·희망·당위 표현을 실제 변화로 분류하지 않는다. 실제 예정/승인 보도는 보존한다.
- 동일 시설 정비 또는 행사명·행진 경로·도착지·시간이 명시적으로 맞는 보도를
  7일 이내 범위에서 묶는다. 단순히 같은 지역이라는 이유로 합치지 않는다.
- 각 출처와 관련 문장, 게시일, 예정/완료 등 단계는 supporting_facets에 보존한다.
  묶음은 텍스트 기반 대응이며 실제 사건 동일성·점포 반경 영향의 인증이 아니다.
- Critic/Brief에도 질문 오분류 방어를 넣어 과거 결과의 질문을 변화 카드에서 제외한다.

| 실제 지역 | 개선 전 확인 문제 | 최종 묶음 |
|---|---|---|
| KT플라자 동래점 / 명륜동 | 인터뷰 질문이 직접 변화로 분류, 지하차도 기사 중복 | 질문은 직접 변화에서 제외. 내성지하차도 관련 4개 출처를 1개 묶음으로 보존 |
| KT플라자 광화문중앙점 / 새문안로 | 같은 개천절 행진을 기사 문장 차이로 여러 카드에 표시 | 동일 경로·도착지·시간의 3개 출처를 1개 묶음으로 보존 |

최종 동래는 출처 15개/인사이트 12개: 직접 변화 1, 주변 맥락 5, 배경 2, 미분류 4.
광화문중앙은 출처 14개/인사이트 12개: 직접 변화 1, 주변 맥락 3, 미분류 8.
미분류·원문 미대조 검색 후보는 변화 브리프에서 제외한다.
동래 인터뷰 기사 전체를 무조건 버리지는 않고, 질문 이외에 확인한 내용은 보조 맥락으로 남긴다.

## Critic 진단

Quant 관측 인사이트에 실제 소상공인365 source_id를 연결했다. 새 결과에서
EVIDENCE_LINK_UNAVAILABLE 오탐 5건은 사라졌다. 공식 관측값의 LLM 재인증은 하지 않는다.
두 지역 모두 규칙 오류 0건/제외 모듈 0개다. 각 5개 제약 진단은 Scout 경고 3개와
Local/Trend partial 2개이며 전체 조사 실패가 아니다.

checks.diagnostics는 규칙 오류, 자료 제약, 제외 모듈, GPT 실행 상태/코드,
사례 판정 건수를 구분한다. Brief에도 GPT 완료/꺼짐/미완료를 명시한다.
manual_review는 사람의 기획 판단을 남기는 상태이며 GPT 미실행이나 실행 실패와 다르다.
고정된 최소 신호 2개/비교 차이 1개라는 과거 초안 요구는 보완 안내에서 제거했다.

## 실제 두 지역 Trend 비교

기준일 2026-10-04, 조회 기간 180일, 요청 반경 1,000m.
Kakao 정확 명칭으로 두 매장을 찾고 Quant/Local을 실제 조회했다.
광화문은 이름이 모호한 ‘광화문점’ 대신 정확한 ‘광화문중앙점’이다.

| 관측 축 | 동래점 선택 영역 | 광화문중앙점 선택 영역 |
|---|---|---|
| 유동인구 주요 연령 / 비중 | 60대 이상 / 37% | 60대 이상 / 24% |
| 유동인구 주요 성별 / 비중 | 남성 / 52.7% | 남성 / 56.5% |
| 매출 금액 주요 연령 / 비중 | 60대 이상 / 58.3% | 20대 / 36.1% |
| 매출 금액 주요 성별 / 비중 | 남성 / 58.9% | 여성 / 59.7% |
| 유동인구 최다 요일·시간 | 목 / 14–18시 | 수 / 14–18시 |
| 매출 최다 요일·시간 | 토 / 14–18시 | 금 / 14–18시 |

성별과 연령은 서로 독립된 분포다. 매출 비중은 구매자 수가 아니며 개별 KT 점포의
실적도 아니다. 표의 미표시 기준 시점은 미확보 상태로 남긴다.

실제 비교 중 발견한 연결 오류도 수정했다. 요일/시간대 cards의 shares가 인구 프로필을
덮어쓰면서 주요 성별·연령을 지우고 있었다. 이제 인구 분포만 demographic context에
사용하고, 별도 매출 성별·연령 표는 각각의 관측을 보존하며 연결한다.
유동·매출·주거·직장 4개 모집단의 전체 분포가 전달됨을 확인했다.

전국 뉴스 검색 3개/YouTube 검색 3개의 같은 신선한 자료를 두 지역에 재사용해
검색 시점·호출 한도의 영향을 통제했다. 지역마다 뉴스 10개+YouTube 10개 후보를 남겼고
provider 오류는 없었다. 참고 사례는 각 5개이며 3개가 겹쳤다.
공통 사례 3개 모두 응용 질문은 달랐다. 전체 관측이 질문을 바꾸는 것이며
성별·연령별 선호가 검증되거나 두 지역에 완전히 다른 행사를 추천했다는 뜻은 아니다.

예를 들어 매출 연령 분포가 한 연령에 집중된 동래에는 주요 연령의 사용 장면과
다른 연령도 선택 가능한 장면을 함께 비교하는 질문이 붙었다. 광화문중앙에는
매출 연령 비중이 분산되어 여러 장면을 직접 고르는 비교 질문이 붙었다.
남녀 비중이 60%를 넘지 않는 매출 표에는 성별을 좁히지 않는 질문이 붙었다.
50%/60%는 기존 질문 설계 규칙이며 통계적 유의성·흥행 임계값이 아니다.

Local의 후속 행사 묶음 정리는 같은 실제 기사 대조 기록을 재생한 검사다.
최종 전국 비교도 최초 수집한 뉴스/YouTube 자료를 재사용했으며 새로 확보하지 않은
사실을 추가하지 않았다. 기사 본문 대조는 영상 시청/댓글 분석이나 실제 행사·호응 인증이 아니다.

## GPT 최종 검토 결과

실제 API 호출을 수행했다. 예비 검토와 실패 1회를 포함해 시도는 총 5회다.
동래 예비 응답 1개는 INVALID_RESPONSE로 채택하지 않고, 브리프를 보존했다.
등급 일관성 및 가설/과장 구분 지침을 보정한 뒤 최종 브리프에는 지역별 1회씩 호출했다.
자동 재시도 루프는 추가하지 않았다. API 키·토큰·인증 URL 값은 출력/커밋하지 않는다.

| 최종 검토 | 지역·고객 연결 | 응용 차별성 | 과장 | 판정 |
|---|---|---|---|---|
| 동래 사례 5개 | clear 2 / weak 3 | generic | clear | generic 5 |
| 광화문중앙 사례 5개 | weak | generic | clear | generic 5 |

초기에는 가설 수준이나 행사 반응 미확보만으로 과장 위험을 주는 경향이 있었다.
보정 후 최종 응답에서는 그 10개 모두 overclaim=clear다. 다만 과장 없음은
기획 품질 승인이나 사실 인증이 아니다. GPT가 근거 없는 교차 고객군 표현을
생성한 이유/제안에는 코드가 보정 표시를 붙였다. 최종 4개 사례에 보정이 있어
GPT 원문을 무조건 신뢰할 수 없다는 한계도 확인됐다.

결론은 ‘지역 입력이 무의미’가 아니라 ‘관측에 따라 질문은 달라지지만
기능 비교·촬영·굿즈 같은 응용 템플릿은 아직 범용적’이라는 것이다.
GPT 의견도 참고 판정이며 사람이 검토해야 한다. 후보에는 홍보대사 위촉·여러 행사를
모은 기사처럼 직접적인 체험 구조 연결이 약한 자료도 있어 사례 단위 정합성 개선이 남는다.

## 다음 개선과 범위 한계

다음 품질 작업은 **전체 분포·모집단/시간 차이·Local 사건을 선택적으로 조합해
서로 다른 2~3개 연구 방향을 만드는 것**이다. 각 방향에 실제 관측 근거와
왜 다른 방향과 차이가 나는지 적고, 단순 고정 질문 추가를 줄인다.
이는 제품이나 실행 계획을 SPoT가 먼저 확정하는 기능이 아니다.
후속 기획에서 사용자가 선택한 제품·가치·목적과 결합한다.

Local은 최대 15개 원문 후보, 지역명/도로명 기반이며 실제 반경·뉴스 전체를 검증하지 않는다.
Trend도 검색 3개/참여 방식 분류 규칙에 따른 제한된 탐색이다.
소상공인365 연결 정상은 이번 점검 시점의 결과다.
Instagram/Threads 자동 공개 검색은 비즈니스 인증·앱 검수 한계로 보류한다.
상시 서버 배포와 공통 Notion 문서 동기화는 이번 검증에서 수행하지 않았다.
n8n normalization 변경은 저장소 export에 반영했으며 운영 워크플로 게시 변경은 하지 않았다.

회귀 검증: Python 225개와 JavaScript 검사 파일 6개 모두 통과했다.
질문/희망과 실제 예정 보도 구분, 사건 경로·시간/7일 범위, 과거 브리프 질문 제거,
분포 덮어쓰기/분리된 성별·연령 표 연결, API 기본값 및 n8n/웹 입력을 확인했다.
두 지역의 실제 Scout/GPT 저장 결과를 HTTP 접수→큐→전체 그래프→브리프에 재생했고
두 건 모두 completed, GPT 진단 completed, Local 묶음 1개로 반환됐다.
이 통합 재생에는 새 외부 호출이 없으며 운영 n8n을 거친 새 조사 검증은 아니다.

검증 기록은 ignored `.venv/verification/location-quality/`의 실제 입력·정량 내부 archive,
provider cache, 최종 reviewed JSON 및 비교/PDF/Markdown에 보관했다.
이 기록을 Git에 올리거나 API 인증 값을 공개하지 않는다.
