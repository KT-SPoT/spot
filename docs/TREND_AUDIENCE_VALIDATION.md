# Trend 연령·성별 반영 비교 — 2026-10-03

## 결론

현재 Trend의 고객층 반영은 부분적이다. 저장한 실제 검색 자료에 고객층만 바꿔
넣은 6개 조건 모두 **같은 참고 사례 5개를 같은 순서로 선택**했다. 후보 점수도
같았고, 공통 사례의 매장 응용 문장과 후속 조사 질문도 같았다. 인구 신호와
성별·연령 표기는 출력에 전달되지만 응용 내용은 아직 충분히 달라지지 않는다.

사례가 겹친다는 이유만으로 잘못된 결과라고 판정하지 않는다. 전국의 공통 체험
사례도 서로 다른 고객층에 유용할 수 있다. 다만 고객층별 연결 이유·검토할
사용 장면·다른 점을 확인할 질문까지 똑같으면 실질적 반영이 약하다고 본다.

## 비교 조건

- 점포와 상품: 저장된 명지국제신도시 / Galaxy Z Fold8 요청을 고정.
- 조사 기준일: 원래 수집의 `2026-10-02`를 유지. 오늘 새 검색 자료로 표시하지 않음.
- 자료: 네이버 실제 검색 응답 3개 검색어 × 최대 2페이지, 600행(이전 기록상 고유 URL 573개).
- 고객층: 20대·40대·60대 이상 × 남성·여성, 총 6개 합성 개입.
- 같은 모집단(유동인구)의 주요 연령·주요 성별만 변경. 두 주변 분포를 결합해
  실제 `20대 남성 고객` 수를 주장하지 않으며 원래 Quant 관측값은 수정하지 않음.
- 점포·상품·날짜·Local 맥락·뉴스 입력·원문 대조 결과는 모든 조건에서 동일.
- 저장된 원문 확인 결과도 재생. 기사 출처 ID는 현재 결과의 ID에 맞게 다시 연결.
- **새 네이버·YouTube·GPT·기사 조회 모두 0회**. 현재 자동 Trend의 반영 정도를
  측정하며 GPT Critic의 입력별 평가 차이는 이번 실험 범위가 아님.

참고 사례는 기존 진주남강유등축제 관광스타트업, 더후 NAD 팝업, Sweet Agent,
노브랜드 버거 × 애니모, 지스타 × KREAM이다. 선호도·인기도·성과를 비교한
것이 아니며 신규 방문자 조사도 수행하지 않았다.

## 원인과 작동하는 부분

1. `build_queries()`는 게임·음식 팝업과 지역 축제라는 전국 공통 검색어 3개를
   사용한다. 이는 연령 단어로 검색 폭을 과도하게 좁히지 않기 위한 기존 결정이다.
2. `context_fit()`은 기사 제목·검색 요약에 고객층 표현이 있을 때만 소폭 점수를
   더한다. 이번 자료에서는 6개 조건 사이의 점수 차이가 발생하지 않았다.
3. `adaptation_hypotheses()`는 체험 구조와 상품으로 문장을 만들며 성별·연령은
   인자로 받지 않는다. 동일한 체험 구조에서는 같은 응용 문장이 나온다.
4. `audience_fit_questions()`는 유동·주거·직장·매출 모집단별 목적을 나누지만
   각 모집단 안에서 연령·성별별 rationale/next_check는 같은 틀을 사용한다.
5. 고객층 자료가 없으면 audience_fit을 생성하지 않고, 유동인구와 매출 고객층이
   다른 혼합 입력은 두 모집단을 분리한다. 반복 실행도 같은 결과를 반환한다.
6. 합성 기사에 고객층 표현을 넣은 대조 검사에서는 후보 점수 차이가 발생했다.
   따라서 전달 경로가 끊긴 문제라기보다 실제 자료의 표현 의존과 문장 생성 범위의 문제다.

## 다음 개선 기준

후속 개선 추적: [Issue #34](https://github.com/KT-SPoT/spot/issues/34).

- 전국 공통 탐색은 유지하되, 고객층을 직접 언급한 근거가 있다면 그 근거가
  선정 이유에 어떻게 기여했는지 표시한다. 기사에 표현이 없을 때 일률적으로
  낮은 품질로 판단하지 않는다.
- 매장 응용 단계가 전체 분포·모집단·시간대·Local 맥락을 읽고, 사례의 실제
  참여 구조와 연결한 검토 질문을 만들도록 개선한다. 출력 차이 자체를 목표로 삼지 않는다.
- `젊으면 게임`, `여성이면 뷰티` 같은 성별·연령별 고정 업종 배정은 하지 않는다.
  선호 근거가 없으면 선호를 단정하는 대신 어떤 사용 장면·참여 방식의 적합성을
  비교할지 제안한다. 같은 사례·질문이 타당하면 그 공통 이유도 설명한다.
- 추가 고객층 정보가 없는 상태에서 GPT Critic만 반복 호출해도 원래 Trend의
  고정 응용 문장은 바뀌지 않는다. 개선 대상은 사례 선정 이유와 응용 생성 단계다.

## 재현과 회귀 검사

```bash
python -m src.evaluation.trend_audience \
  --bundle .venv/verification/trend-evidence-fit/result.json \
  --cache .venv/verification/nationwide-trend-live/search_cache.json \
  --output .venv/verification/trend-audience-validation
python -m unittest tests.test_trend_audience_evaluation -v
```

실제 응답과 상세 출력은 로컬 ignored 경로에 보관한다. 이 문서에는 집계와
검증 범위만 기록한다. 평가기는 요청한 검색어가 캐시에 없으면 중단하며 새
provider 호출로 대체하지 않는다. 성별·연령 표기만 바뀐 경우를 실질적 응용
차이로 세지 않는다. 부족한 참고 자료는 판정 불가로 표시한다.

새 회귀 검사는 표기만 바뀌는 결과 감지, 메타데이터 매칭의 점수 변화,
고정 자료의 불변성·외부 호출 차단, 누락 캐시 중단, 자료 미확보 판정,
기사 출처 ID 재연결과 공통 사례에 한정한 질문 비교를 확인한다.
